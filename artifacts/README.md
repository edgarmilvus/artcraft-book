# Output snapshots

A full, green run of the book produces about 15,000 files and roughly 180 MB of
artifacts: 2,266 of them across 147 project output folders are the ones worth
keeping. They ship as **release assets** on this repository, tagged
[`outputs-v1`](../../releases/tag/outputs-v1), so you can inspect the expected
result without building anything and restore your own outputs after a run has
overwritten them.

| archive | chapters | entries | packed |
| --- | --- | --- | --- |
| `artcraft-outputs-ch01-10.zip` | 1 to 10 | 1,079 | 62 MB |
| `artcraft-outputs-ch11-20.zip` | 11 to 20 | 1,914 | 55 MB |

The archives are not committed: a clone should stay small, and a zip of a
rendered PNG is not worth 117 MB of everybody's bandwidth. The checksums are
committed here, so a download can be verified against the same bytes the run
produced.

Snapshot taken on 2026-10-26, from a run in which all twenty chapters reported
no failures. The exercise folders were renamed on 2026-10-27, so the paths
inside the archives follow the current layout; the artifacts themselves are
unchanged.

## What stays in the tree

Each project keeps the proof that its harness ran, and its inputs:

- `run_*.log` — the harness log, one line per assertion;
- `manifest*.json`, `report*.json`, `*.sha256` — the machine-readable record;
- one preview image per project, small enough to read inline;
- every fixture the harness needs as an *input*.

What does not stay is the bulk: HDR masters, `.pcraft` documents, WAV renders,
MP4s and the large PNGs. Those are reproducible, they are in the archives, and
they are ignored by `.gitignore` so a later run does not put them back.

## Restore

From the root of the repository, after downloading the two assets into
`artifacts/`:

```bash
gh release download outputs-v1 --pattern '*.zip' --dir artifacts
cd artifacts && shasum -a 256 -c SHA256SUMS
unzip artcraft-outputs-ch01-10.zip
unzip artcraft-outputs-ch11-20.zip
```

Paths inside the archives are relative to the repository root, so every file
lands back in its own project folder. Nothing is overwritten that a run of
`./run_all.sh` would not rewrite anyway.

## What is inside, and what is not

The archives mirror what a run leaves under each project's `output/` or
`files/output/` folder, plus the runner's own log.

The runner's log is included for chapters 4, 5 and 6, because for those
chapters it is the only output: their harnesses write to a temporary directory
and clean up after themselves, or produce nothing at all. Elsewhere the log is
regenerated by every run.

Two Chapter 1 scripts call a language model and need an API key, so the runner
skips them. Their artifacts are committed in the repository and are included
here; `chapter1/verify_examples.mjs` checks them.
