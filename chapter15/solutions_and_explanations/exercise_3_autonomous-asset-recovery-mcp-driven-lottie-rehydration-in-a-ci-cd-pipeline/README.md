# 15. Exercise 3: Autonomous Asset Recovery — solution

The worked bounded rehydration. It detects Lottie assets that point outside the
bundle, regenerates them as content-addressed PNGs, and rewrites the
composition to relative paths that pass the schema and need no second pass.

## What it does

1. `detectUnmapped()` classifies each asset as `absolute-path` or
   `wrong-platform` and ignores relative paths. A healthy file produces zero
   work, which makes the repair idempotent.
2. `guarded()` wraps every MCP call; the 13th call throws
   `RecoveryBudgetExceeded` (`MAX_MCP_CALLS = 12`).
3. `Transcript` keeps the newest notes and trims the file to 200 lines.
4. `validateLottie` is an AJV schema over the Lottie v5.7 surface the pipeline
   relies on (`v`, `fr`, `ip`, `op`, `w`, `h`, `nm`, `ddd`, `layers`, optional
   `assets`).
5. The repair hashes the generated bytes, renames to `glow-<sha16>.png`,
   rewrites `u`/`p` to `recovered-assets/`, validates the healed document and
   writes the plan and transcript.

## Notes

- The 200-line cap is a hard ceiling: a test that writes 300 notes still
  produces 199 lines because each note ends with a blank line.
- The heal is content-addressed, so a rerun that produces identical bytes
  lands on the same filename and the rewrite stays stable.
- `--dry-run` is not part of this exercise; the harness runs the pure path so
  no engine or network is required.
- Type-check it with `npm run check`.
